## Integration approach — three options

| Option | Coupling | Build effort | Recommended? |
|---|---|---|---|
| **A. MCP client** — capstone is an MCP-aware LLM agent that calls `kg-mcp` over stdio or HTTP | Loose | Low (config + LLM client) | **Yes — primary** |
| B. Direct Python import — capstone is a Python app that imports `vidya_karana_kg` and `vidya_karana` packages | Tight | Medium (vendor / dev-install both) | Fallback if MCP latency hurts |
| C. HTTP/REST — capstone hits `vidya-karana-kg`'s FastAPI endpoints | Loose | Low | Useful if capstone runs on a different machine than the corpus |

**Recommended primary: A (MCP).** Reasons: (1) the MCP server is already built, tested, and exposed via launchd; (2) capstone can swap LLM providers without rewriting retrieval glue; (3) loose coupling = capstone is portable, can be shared with the family in v2 without forcing them to install ChromaDB and the corpus on every device.

**Local-first preserved:** the MCP server runs on the user's machine. No data leaves. Bearer-token auth on the FastAPI endpoint can be reused if remote access is ever needed.

## Pattern surfacing at small N (methodology)

From the research agent that succeeded — full version saved as appendix; key rule below.

### The Saturday-firing rule

Surface a pattern only if **all** hold:

1. **N ≥ 21** observed days (3 weeks minimum; below this, surface only descriptive recaps).
2. The predictor is on a **pre-registered short list** (≤3 candidates per phase, chosen by the user or fixed in config).
3. The association meets **|Spearman ρ| ≥ 0.35 AND a Bayes factor ≥ 3** against the null (JZS prior; `BayesFactor::correlationBF` or equivalent).
4. The pattern **survived BH-FDR at q=.10** across the pre-registered set.
5. The pattern is **stable** — also visible in the most recent 14-day window (not just driven by week 1).

Otherwise: **say nothing.** Or surface a descriptive recap: *"This week: 5 of 7 days completed; median sleep 10:52 PM."*

### Honest phrasings (ranked)

- **Defensible (raw counts).** *"This week, on the 5 days you completed your rounds, you were in bed by 10:45 PM on 4 of them. On the 2 incomplete days, you were in bed by 10:45 PM on 0."* — Just counting.
- **Defensible at N≥30 with rule passed.** *"Across the last 30 days, completing rounds and sleeping by 10:45 PM the night before have co-occurred more often than chance would predict (ρ=0.41; weak-to-moderate association, not proof of cause)."*
- **Borderline.** *"Sleep before 10:45 PM is associated with rounds completion this week."* — Avoid until N≥30.
- **Forbidden.** *"Sleeping by 10:45 PM helps you complete japa."* — Causal. Never use observationally.
- **Forbidden, gamified.** *"Hit your 10:45 bedtime to unlock tomorrow's rounds!"* — Manipulative; violates sattvic constraints.

### Honest null-result reporting

The most important template the agent can use (and the most missing in commercial habit-trackers):

> *"I checked for patterns this week and didn't find one worth naming. Here is your raw week: …"*

### What none of them do (the real gap)

Cross-referencing the existing landscape against `01_grill.md`:

- **Weekly Saturday check-in** with rotating sastra-rooted questions — no one does this.
- **Tone / mood (bhava) / practices / priorities sankalpa-setting** — no one does this.
- **Pre-japa quote + practical tip**, sourced from a real corpus with citations — no one does this. (The pure counters have generic motivational quotes at best.)
- **Hearing ↔ chanting loop** as the explicit product shape — no one does this.
- **Pattern surfacing with honest null-result reporting** — no one does this; everyone gamifies.
- **Silence during japa as a design feature** — no one does this; most pulse / vibrate.
- **LLM responses grounded in a verified Vaishnava corpus** — no one does this (the corpus didn't exist publicly until vidya-karana-kg).

### What to explicitly avoid (lessons from the landscape)

- **Streaks-and-badges gamification.** Nearly every existing app has streaks. They're addictive by design — sattvic constraints forbid this.
- **"Lifetime count" as motivator.** [JapaCounterOnline](https://japacounteronline.in/)'s own copy is the giveaway: *"strongly increases daily follow-through and habit formation."* This is the productivity-app framing the user explicitly rejected in Phase 1.
- **Push notifications during sadhana windows.** Already a hard constraint in `01_grill.md`.
- **Mentor-share / social surveillance.** My Sadhana App's model. We chose family-mode for v2 with care framing, not monitoring.
- **Multi-area tracking that turns sadhana into a chore matrix.** Same lesson.

### One worth learning from

Chanting Monitor's audio-driven counting is genuinely innovative. **Defer to v3** — useful only if typed/tapped count proves a friction point.

### Family-mode primitives

Deferred to v2. The data model in v1 should *not preclude* later family extension:

- User-scoped rounds (foreign key on `user_id`, default = self)
- Reflection entries scoped per user
- Long-distance presence channel (father in remote village) is a Phase 2 design exercise — likely phone-call-friendly, not smartphone-first

## Recommendations into PRD

1. **Adopt vidya-karana-kg as the sastra layer.** MCP integration (Option A) primary, Python-import fallback.
2. **Honor the existing graph snapshot cadence.** Nightly cron rebuild already exists. Capstone reads, never writes, the corpus.
3. **Typed input only in v1.** No voice, no STT. Reduces stack, eliminates microphone-permission UX, dodges Sanskrit-STT accuracy risk. Voice deferred to v2.
4. **Pre-register the pattern-surfacing predictor set.** v1 candidates: previous-night sleep time, previous-day rounds completion, ekadasi/non-ekadasi day. ≤3 hypotheses, BH-FDR at q=.10, ≥21 days before first surfacing.
5. **Curate, don't generate, the practical tips.** ~10 written tips per relevant value, cited; LLM not allowed to invent.
6. **Reserve a place for family-mode in the data model**, but ship single-user.
7. **Differentiate explicitly from existing apps**: no streaks, no badges, no lifetime-count motivator, no push notifications during sadhana, no mentor-share, no multi-area chore matrix. The Saturday check-in + hearing↔chanting loop + curated quote+tip + honest null reporting are the four things no existing app does — they ARE the product.
